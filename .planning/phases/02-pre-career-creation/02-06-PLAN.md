**Drag offset fix (UAT test 2, 3, 6):**
The root cause is `animation-fill-mode: both` in `.animate-slide-in` keeps a CSS transform active after the slide animation completes, which creates a new containing block for DragOverlay's `position: fixed`. Fix by changing the animation approach:

In `src/index.css`, change `.animate-slide-in` from `animation-fill-mode: both` to `animation-fill-mode: forwards`. Then change both keyframes so they end at `transform: none` (not `translateX(0)`) to ensure the transform is fully removed after animation completes. Alternatively, use `animation-fill-mode: none` and set the default state to the "to" state (opacity 1, no transform) so the animation plays and then the element snaps to its natural non-transformed state.

The cleanest fix: remove `animation-fill-mode: both` entirely and set `animation-fill-mode: none`. Then update both keyframe `to` blocks to `transform: none; opacity: 1;`. This ensures no residual transform after animation.

**Session persistence (UAT test 5):**
1. In `src/stores/character.ts`: Add `persist` middleware from `zustand/middleware` wrapping the immer middleware. Configure with `name: 'starmaker-character'`, `storage: createJSONStorage(() => sessionStorage)`. Persist all state fields (characteristics, skills, rollLog, legitimacyHash, isModified). Import `persist` and `createJSONStorage` from `zustand/middleware`.

The middleware chain should be: `create<CharacterStore>()(persist(immer((set) => ({...})), { name: 'starmaker-character', storage: createJSONStorage(() => sessionStorage) }))`.

Add a `dicePool: PoolItem[]` field to CharacterState and a `setDicePool: (pool: PoolItem[]) => void` action. In the component, read from `useCharacterStore((s) => s.dicePool)` instead of local useState, and call `setDicePool(results)` in handleRollAll. Define the PoolItem type in the store or in `src/types/dice.ts` (whichever is cleaner). This ensures the dice pool survives refresh.

3. In `src/hooks/useCreationMachine.ts`: On mount, read persisted store data to derive the correct initial machine state. After creating and starting the actor, check `useCharacterStore.getState()`:
