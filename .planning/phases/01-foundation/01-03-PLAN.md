  <behavior>
**XState Creation Machine (FNDN-05):**
- Machine starts in `idle` state
- `START_CREATION` event transitions from `idle` to `characteristics`
- `CHARACTERISTICS_COMPLETE` transitions from `characteristics` to `backgroundSkills`
- `BACKGROUND_COMPLETE` transitions from `backgroundSkills` to `education`
- `EDUCATION_COMPLETE` transitions from `education` to `career` (education is optional — user may skip or attend)
- `CAREER_TERM_COMPLETE` transitions within career (can loop for multiple terms)
- `MUSTER_OUT` transitions from `career` to `musteringOut`
- `MUSTERING_COMPLETE` transitions from `musteringOut` to `complete`
- `complete` is a final state
- Invalid transitions are rejected (e.g., cannot go from `idle` to `career` directly)
- Machine context tracks: `currentPhase` (string), `characterId` (string), `termsServed` (number)
- Uses `setup().createMachine()` pattern for full TypeScript inference
- Guards exist for: `hasCharacteristics`, `hasBackgroundSkills` (placeholder implementations returning true — real logic comes in Phase 2)

**Zustand Character Store (FNDN-06):**
- Initial state: empty characteristics (all 0), empty skills array, empty roll log, empty legitimacy hash, isModified=false
- `setCharacteristic(id, value)` updates a single characteristic immutably
- `addSkill(name, level)` adds a skill to the skills array
- `updateSkillLevel(name, level)` updates an existing skill's level
- `appendRoll(entry)` appends a RollLogEntry to the roll log immutably
- `setLegitimacyHash(hash)` sets the hash string
- `setModified()` sets isModified to true
- `resetCharacter()` returns store to initial state
- All mutations use Immer — direct property mutation in the updater function, but the store state is actually immutable
- Store uses Zustand 5's `create<T>()(immer((set) => ...))` pattern
  </behavior>

1. `src/machines/creation.ts`:
   Use XState 5 `setup().createMachine()` pattern:
   ```
   setup({
     types: { context: ..., events: ... },
     guards: { hasCharacteristics: () => true, hasBackgroundSkills: () => true },
   }).createMachine({
     id: 'creation',
     initial: 'idle',
     context: { currentPhase: 'idle', characterId: '', termsServed: 0 },
     states: {
       idle: { on: { START_CREATION: 'characteristics' } },
       characteristics: { on: { CHARACTERISTICS_COMPLETE: 'backgroundSkills' } },
       backgroundSkills: { on: { BACKGROUND_COMPLETE: 'education' } },
       education: { on: { EDUCATION_COMPLETE: 'career' } },
       career: {
         on: {
           CAREER_TERM_COMPLETE: 'career',  // loop
           MUSTER_OUT: 'musteringOut'
         }
       },
       musteringOut: { on: { MUSTERING_COMPLETE: 'complete' } },
       complete: { type: 'final' }
     }
   })
   ```
   This is the skeleton — nested sub-states for each step will be added in Phase 2-3.
