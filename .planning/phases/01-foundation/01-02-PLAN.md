  <behavior>
**Dice Engine (FNDN-02):**
- `rollDie(6)` returns integer 1-6
- `rollDie(3)` returns integer 1-3
- `rollDice(2, 6)` returns array of 2 integers, each 1-6
- `roll1D()` returns single die result 1-6
- `roll2D()` returns sum of 2D6 (range 2-12)
- `roll3D()` returns sum of 3D6 (range 3-18)
- `rollD3()` returns integer 1-3
- `rollD66()` returns D66 value (11-66, tens*10+ones, each die 1-6)
- `rollDie(0)` and `rollDie(-1)` throw errors
- Uses `crypto.getRandomValues()` with rejection sampling (NOT modulo)
- Over 10,000 rolls of 1D6, chi-squared test passes at p=0.01 (distribution is uniform)

**Roll Log (FNDN-03):**
- `createRollLogEntry(context, notation, results, modifier?, target?)` returns a valid `RollLogEntry` with UUID id, calculated total, overridden=false
- `appendToLog(log, entry)` returns a NEW array (immutable) with entry appended
- `appendToLog` does NOT mutate the input array
- Roll log entries validate against the Zod schema from `src/schemas/roll-log.ts`
- Context strings follow dot-path convention (e.g., `"characteristics.STR"`)

**Legitimacy Hash (FNDN-04):**
- `canonicalizeRollLog([])` returns a consistent string for empty log
- `canonicalizeRollLog(entries)` produces deterministic output (same input = same output, always)
- `canonicalizeRollLog` uses only `id`, `context`, and `results` fields (no timestamps, no modifier, no total)
- `canonicalizeRollLog` sorts object keys alphabetically
- `computeHash([])` returns the hash of an empty log (not empty string — hash of the canonical empty representation)
- `computeHash(entries)` returns 8-character hex string (truncated SHA-256)
- Same entries in same order = same hash (deterministic)
- Different entries = different hash (collision resistance for practical purposes)
- Reordering entries changes the hash (order matters)
  </behavior>
